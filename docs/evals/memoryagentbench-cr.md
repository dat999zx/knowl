# MemoryAgentBench — Conflict Resolution results

**Benchmark:** [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench) (ICLR 2026, MIT),
Conflict Resolution track, `factconsolidation_sh_6k`.
**Date:** 2026-07-27. **Dataset:** `ai-hyz/MemoryAgentBench`, Conflict_Resolution split, row 4.

Conflict resolution is defined by the benchmark as *"detecting and overwriting outdated facts when
new, contradictory information is introduced, ensuring subsequent queries reflect only the newest
valid data."* It is the public benchmark closest to what Knowl's write path is built to do.

---

## Result

Same corpus, same retrieval path, same metric. The only thing that changes between rows is
whether Knowl is allowed to retire a superseded fact.

| Configuration | top-1 accuracy | stale leaks | active atoms after ingest |
| --- | --- | --- | --- |
| **Supersession ON** (shipped behaviour) | **96.0%** | 3 / 100 | 306 |
| Supersession OFF (ablation) | 40.0% | 62 / 100 | 455 |

**Governance is worth +56.0 points of top-1 accuracy**, and cuts stale answers from 62 to 3.

Run detail: 455 facts ingested, 156 conflict groups detected, **149 facts retired at write**.
100 questions, top-*k* 5, vector+BM25, p50 19 ms / p95 21 ms, 0 empty results.
Raw per-question results: [`benchmarks/memoryagentbench/results/`](../../benchmarks/memoryagentbench/results/).

Reproduce:

```bash
npm run bench:cr -- fetch --row 4
npm run bench:cr -- run --instance benchmarks/memoryagentbench/data/cr-sh-6k.json --top-k 5
npm run bench:cr -- run --instance benchmarks/memoryagentbench/data/cr-sh-6k.json --top-k 5 --no-supersede
```

## How to read this against published baselines

Published CR-SH baselines are **long-context agents 45.0%** and **best RAG method 56.0%**.

**Those are not the same measurement as the number above, and should not be subtracted from it.**
The published figures are end-to-end accuracy of an LLM reader answering from the memory system.
The number here is *retrieval-level*: whether the single highest-ranked atom Knowl returns contains
the gold value, scored by the benchmark's own substring exact match. No LLM is involved, so there
is no reader to make or lose points.

What that means in practice:

- The **ablation is the rigorous claim.** It is internally controlled — identical data, retrieval,
  scoring and machine — so +56.0 points is attributable to supersession and nothing else.
- The **comparison to 45% / 56% is indicative only.** It suggests Knowl's approach is well suited
  to this task; it does not establish a leaderboard position. Claiming otherwise would be
  comparing a retrieval metric against a reader metric.

An end-to-end reader run would make it directly comparable. That needs a working LLM provider,
which is not currently configured.

## Protocol, preregistered

| Choice | Value | Why |
| --- | --- | --- |
| Instance | `factconsolidation_sh_6k` (row 4) | Single-hop first; see *Not attempted* for multi-hop |
| Ingestion | one atom per fact, in context order | Recency comes from stream order alone |
| Title | subject+relation, derived from fact text | The supersession rule keys on titles — see below |
| Content | the full fact sentence | What gets returned and scored |
| Retrieval | vector + BM25, top-*k* 5 | The path Knowl actually ships |
| Metric | substring exact match on the **top-1** atom | The benchmark's metric, at the strictest rank |
| Isolation | one fresh store per run | No leakage between configurations |

### The titling rule, and why it is not cheating

Knowl's automatic supersession keys on titles: `sameSubjectTitle` retires an existing item when the
incoming title names the same subject. So the harness must give each fact a title, and that choice
decides whether the mechanism engages at all.

Titles are derived by **shared-prefix discovery over the fact text only**. An update is generated by
swapping the final value of an existing sentence, so the pair shares everything up to that value:

```
goaltender is associated with the sport of | ice hockey     <- earlier
goaltender is associated with the sport of | pesäpallo      <- later, and the gold answer
```

Sorting the fact list puts such pairs adjacent, so one linear pass recovers the shared stem. A fact
with no partner keeps its whole sentence as its key and can never supersede anything.

**This reads the facts and nothing else.** It never consults the questions or the answer key. A rule
that peeked at which value was gold would be manufacturing the result rather than measuring it. The
guard against over-merging is a minimum ratio: `The chairperson of` is shared by facts about Fatah
and about Harvard, but it is far shorter than either sentence, so it is rejected as a key.

This is also what a real deployment does — Knowl delegates extraction to the client model, and a
real agent titles atoms by subject. The harness is a deterministic stand-in for that step.

### Metric detail

`staleLeaks` matches the **whole retired sentence**, not the retired value. An earlier version
matched bare values and reported 26 false leaks, because a gold of `India` also appears in five
unrelated facts. Matching the full sentence fires only when the actually-superseded record is
returned.

`anyRankAccuracy` (100% in both configurations) is published as a diagnostic and deliberately
**not** the headline. Both rows retrieve the right fact somewhere in the top 5; only the
supersession row reliably puts it first and suppresses the stale alternative. Leading with
any-rank would hide exactly the difference the track exists to measure.

## What this track does *not* establish

Two scope limits worth stating before the number is quoted elsewhere.

**It tests one conflict type.** Every conflict here is *dynamic*: a value changed, and the newest
statement is correct. That is precisely the rule Knowl implements — `sameSubjectTitle` retires the
predecessor unconditionally — so the benchmark is aligned with the design by construction. A
result here is evidence for "Knowl handles value updates", not for "Knowl handles conflicting
memory" in general.

[MemConflict](https://arxiv.org/abs/2605.20926) formalises three kinds — dynamic, static and
conditional — and reports that *"static conflicts remain difficult at the memory level... stable
factual memories are hard to surface once later contradictory mentions are present."* A static
conflict is one where the stored fact stays true and a **later mention is wrong**.

**Hypothesis, not a measurement:** Knowl's unconditional latest-write-wins rule would retire the
correct fact in exactly that case, so it should be expected to do badly on static conflicts. That
is a design limitation rather than a harness artifact, and this benchmark cannot detect it because
its data contains no such case. It is worth testing before the claim is broadened.

**Peer context is thin.** Of the systems in the published table, MemGPT (28.0%) is the only memory
product; the rest are long-context models and RAG variants. Mem0, Zep, Letta and Cognee report on
other benchmarks, so this result places Knowl against baselines rather than against the products
it competes with.

## Not attempted

- **Multi-hop (CR-MH).** Questions chain two facts ("the spouse of the author of X"). Retrieval
  alone cannot chain, which is why every published paradigm scores **≤6%** there. Knowl has no
  special mechanism for it and a low score would be expected and honest.
- **Larger contexts** (32k / 64k / 262k). Same shape, more facts.
- **End-to-end reader accuracy**, for the provider reason above.
